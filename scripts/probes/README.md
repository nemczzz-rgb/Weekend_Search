# TASK-003: проверка интеграций

> Обновление 2026-11-09: пользователь выбрал локальный выпуск и 0 ₽. Бесплатный Яндекс API не подходит по [официальным условиям](https://yandex.ru/dev/commercial/doc/ru/). Раздел о его ключе ниже оставлен только как история диагностического инструмента; текущий путь проверки описан в [ADR-003](../../docs/decisions/ADR-003-local-map-reassessment.md).

Это самостоятельные диагностические инструменты, **не основное приложение Weekend Search**. Они не требуют FastAPI, React, пакетов pip/npm и не разрешают обходить контрольную точку из [плана](../../docs/project/implementation-plan.md).

## 1. Данные KudaGo и статус Codex

Из корня проекта:

```powershell
python scripts/probes/check_integrations.py --kudago --codex
```

Вывод — безопасный JSON: время, статусы, количество проверенных публичных записей, версия CLI. Ключи, профиль аккаунта и исходные ответы не выводятся. Проверяются координаты, актуальные даты и ссылки, а не только HTTP 200. HTTP 403 остаётся ошибкой доступа; по нему нельзя объявлять источник недоступным для всех пользователей.

Для локального отчёта можно добавить:

```powershell
python scripts/probes/check_integrations.py --kudago --codex --output .local/integration-probes/preflight.json
```

Путь вывода разрешён только внутри игнорируемой .local/. При отказе файлового или сетевого окружения запускать из обычного терминала пользователя; настройки безопасности не отключать. Статус входа внутри песочницы может отличаться от обычного терминала.

## 2. Живой App Server и ограничения

```powershell
python scripts/probes/check_integrations.py --codex-live
```

Проверка использует существующий вход **через ChatGPT**. При отсутствии такого входа останавливается до запроса модели. На платный API-ключ не переключается. Веб-поиск и проверка границы расходуют доступный лимит владельца.

Скрипт запускает отдельный App Server в временной папке, без документов проекта, shell, hooks, личных MCP-коннекторов, приложений и субагентов. Профиль разрешает чтение только тестовой папки и минимальных системных путей; запись и командный сетевой доступ запрещены. Веб-поиск выполняется штатным инструментом модели.

Сначала проверяется реальная конфигурация. Унаследованные MCP-записи явно отключаются при перезапуске дочернего процесса: пустая таблица конфигурации сама по себе не удаляет их. Личная конфигурация пользователя не изменяется.

Далее проверяются initialize/account/config, выбранный профиль, завершённый структурированный ответ с наблюдаемым веб-поиском и отсутствие раскрытия случайного **несекретного** файла-канарейки вне разрешённой папки. Любые запросы на клиентские инструменты и дополнительные разрешения отклоняются.

Скрипт закрывает дочерний процесс до удаления принадлежащих ему временных папок. Протокол или несовместимый профиль не ослабляются для получения успешного результата. Отчёт с ошибкой не является подтверждением изоляции. Полнота ограничений приложения дополнительно проверяется при его интеграции в TASK-008.

В этой среде установлен CLI 0.167.0-alpha.3.2. Для этой версии используется именованный профиль permissions, а не пример sandboxPolicy с полем access из другой версии документации. Сверить публичные схемы своей установленной версии можно командой:

```powershell
codex app-server generate-json-schema --out .local/protocol --experimental
```

## 3. Карта, пеший путь, общественный транспорт и телефон

### Текущая проверка OpenStreetMap

После запуска сервера по командам ниже открыть `http://127.0.0.1:8765/osm/`. Страница загружает обычные тайлы OpenStreetMap через Leaflet, считает успешные и ошибочные загрузки и позволяет визуально проверить масштабирование. Если локальный OpenTripPlanner запущен на порту 8801, страница показывает пробный пеший путь и путь с автобусом через ограниченный локальный прокси. Синий пунктир лишь соединяет остановки: точной геометрии автобусной линии в выгрузке нет. Страница сама по себе не закрывает контрольную точку. На физическом телефоне использовать адрес домашней сети, выведенный сервером с `--lan`, и добавить `/osm/`.

Шесть официальных выгрузок наземного транспорта доступны на [портале открытых данных Москвы](https://data.mos.ru/opendata/60661): наборы 60661–60666. Скачанные архивы хранить в игнорируемой `.local/gtfs-probe/`; содержимое отличается по датам публикации. Для просмотра ссылочной целостности и сборки **временного диагностического GTFS**:

```powershell
python scripts/probes/inspect_moscow_gtfs.py .local/gtfs-probe
python scripts/probes/build_moscow_gtfs_probe.py .local/gtfs-probe .local/gtfs-probe/moscow-ground.gtfs.zip --date 2026-11-14
```

Это не готовый источник полного московского проезда: в этих наборах нет метро и `shapes.txt`, а часть ссылок между версиями не совпадает. Живой пробный расчёт на компьютере описан в [отчёте](../../docs/architecture/integration-report.md). Для повторения использовать [официальную инструкцию OTP](https://docs.opentripplanner.org/en/latest/Basic-Tutorial/) с `--build --save`, затем `--load --port 8801` и выполнить `python scripts/probes/check_otp_routes.py`. Физический телефон остаётся непроверенным. Сырые выгрузки и собранный ZIP не помещать в Git.

### Сохранённая проверка Яндекса (не запускать для локального выпуска)

Только компьютер:

```powershell
python scripts/probes/serve_map_probe.py
```

Компьютер и физический телефон в одной домашней сети:

```powershell
python scripts/probes/serve_map_probe.py --lan
```

Сервер выводит localhost и найденные адреса частных интерфейсов. На телефоне открыть адрес Wi-Fi/Ethernet компьютера, а не адрес VPN или виртуального адаптера. По умолчанию порт 8765; изменить можно через --port. Для остановки — Ctrl+C. Скрипт не меняет настройки брандмауэра и не настраивает проброс портов в интернет.

На странице:

1. Выбрать компьютер или физический телефон. Эмуляция не заменяет телефон.
2. Получить в официальном [кабинете разработчика Яндекса](https://developer.tech.yandex.ru/) ключ JavaScript API Яндекс Карт 2.1 и проверить бесплатный тариф без автосписаний. Не подключать платный HTTP Router API вместо JavaScript API.
3. Настроить допустимые HTTP Referer для используемых localhost, 127.0.0.1 и адреса домашней сети. По [официальной инструкции](https://yandex.ru/maps-api/docs/js-api/common/quickstart.html) активация ключа и ограничений занимает до 15 минут. Ключ не присылать в чат и не сохранять в Git.
4. Ввести ключ в поле страницы. Он используется только браузерным SDK Яндекса; локальный сервер не принимает и не сохраняет его. Не показывать ключ на снимке экрана или в адресной строке.
5. Запустить оба расчёта. Страница вызывает pedestrian и masstransit для реальных московских координат, проверяет положительные расстояние и длительность и отображает маршруты на карте.
6. Визуально подтвердить загруженную подложку и реальные маршруты. Это отдельное подтверждение: наличие объекта SDK не доказывает загрузку карты.
7. Зафиксировать результат и скачать безопасный JSON-отчёт. Повторить на втором устройстве.

Ключ, геометрия, расстояния и длительности в отчёт не входят. На сервер передаются только разрешённые статусы проверок; посторонние поля отклоняются. Отчёты хранятся в памяти процесса и исчезают при остановке, поэтому при необходимости скачать их до завершения. Автоматического подтверждения всей TASK-003 по этим отчётам нет.

Сервер обслуживает только три диагностических файла, health и безопасные отчёты. Пути к репозиторию, directory listing и произвольная загрузка файлов не доступны. Отчёт физического устройства является ручным подтверждением, а не независимым доказательством подлинности устройства.

## 4. Проверки самих инструментов

```powershell
python -m unittest discover -s tests/probes -v
node --check scripts/probes/web/probe.js
```

Проверяются ошибочные даты и координаты, недоступный источник, отсутствие данных, запрет записи ключей/геометрии, невозможность засчитать непроверенный телефон и отрицательные результаты, отсутствие клиентских полномочий App Server. Эти тесты не требуют сетевого доступа и не закрывают живую TASK-003.

CLI возвращает ненулевой код, пока весь набор его обязательных условий не подтверждён. Поле gate_passed намеренно остаётся false: консольная команда не подтверждает физический телефон и режим тарифа. Полный результат сводит координатор по [плану](../../docs/project/implementation-plan.md).
