# ADR-004: Публичный сайт из `main` через GitHub Pages

- Дата: 2026-11-12.
- Статус: Согласовано.
- Автор: Alex071004/claude-repo.
- Связанная задача: TASK-031.
- Основание согласования: 2026-11-12 участник Alex071004 сформулировал задачу «сайт всегда должен отражать актуальный `main`». Из предложенных вариантов он выбрал GitHub Pages. Включить Pages в настройках репозитория может только владелица nemczzz-rgb, этим она и подтверждает решение со своей стороны.
- Заменяет / заменено: дополняет ручную публикацию через Sites из [public-sharing.md](../project/public-sharing.md).

## Контекст

Публичная статическая копия интерфейса для друзей лежит на Sites (TASK-018, 026, 028). Её выкладывает владелица вручную со своего компьютера, к GitHub она не привязана. Поэтому сайт отстаёт от `main`, а обновить его может только один человек. В проекте два участника, бюджет 0 ₽, репозиторий публичный.

## Варианты

- GitHub Pages и Actions: бесплатно для публичного репозитория, новые аккаунты и ключи не нужны, публикуется только сборка, прошедшая CI. Минусы — новый адрес, сайт в подпапке `/Weekend_Search/`, нет предпросмотра для PR.
- Cloudflare Pages, Netlify, Vercel: есть предпросмотр PR, но нужен ещё один аккаунт, и из России у этих сервисов бывают перебои с доступом.
- Оставить Sites: адрес не меняется, но публикация остаётся ручной и требует временного ключа через Codex.
- Свой компьютер дома: сайт виден только в домашней сети и только когда компьютер включён.

## Предложение или решение

Публичный адрес — https://nemczzz-rgb.github.io/Weekend_Search/. Workflow [CI](../../.github/workflows/ci.yml) на каждый push в `main` собирает `apps/web` с `PAGES_BASE=/Weekend_Search/`, запускает проверки `web` и `probes` и только при их успехе выполняет задачу `deploy`. Для PR выполняются только проверки, публикации нет. Локальная разработка и сборка для Sites по-прежнему используют корень `/`.

## Последствия и проверка

- Merge в `main` обновляет сайт через несколько минут. Красный CI сайт не меняет, там остаётся предыдущая версия.
- Адрес на Sites перестаёт быть основным. Удалять его или ставить там переадресацию решает владелица.
- Перед первым запуском владелица включает Settings → Pages → Source: GitHub Actions. Без этого задача `deploy` падает.
- Публикуется только статический интерфейс. Python, SQLite и интеграции по-прежнему локальные (ADR-001, ADR-003).
- Как проверить: после merge в Actions есть зелёная задача `deploy`, а страница по адресу выше показывает текущую версию.
