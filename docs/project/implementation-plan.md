## Порядок

`002 → 003 → 004 → 005–009 → 010 → 011 → 012 → 013`.

TASK-003 обязательна до основной реализации. Документированная возможность, моки, отсутствие ошибки установки или эмуляция не заменяют живую проверку. Если нет доступа, ключа или физического телефона, оставить проверку незавершённой; несовместимость утверждать только с воспроизводимым доказательством.

После TASK-004 данные, помощник и фронтенд допускают параллельную работу по согласованному контракту. Один файл — один исполнитель. Контракт и память меняются последовательно координатором; интеграционные изменения собираются последовательно. Роли не запускают агентов автоматически.

## TASK-003: конкретная контрольная точка

Входы: Python, браузер, Codex CLI и вход владельца через ChatGPT, бесплатная карта и источник данных проезда согласно [ADR-003](../decisions/ADR-003-local-map-reassessment.md). Зависимости основного приложения для этой проверки не требуются.

| Проверка | Что является доказательством |
| --- | --- |
| KudaGo | Живые московские места и будущие события; поля координат, времени и источников проверены, не просто HTTP 200 |
| Codex: вход и протокол | Отдельный App Server отвечает на initialize/account/config; вход через ChatGPT, не платный API-ключ |
| Codex: поиск | Завершён живой запрос со структурированным ответом и наблюдаемым вызовом веб-поиска |
| Codex: ограничения | Реальная конфигурация и ограниченный доступ подтверждены; помощнику недоступны shell, репозиторий, личные коннекторы |
| Компьютер | Реальная карта, пеший и общественный маршруты рассчитаны и показаны из доступных источников; соблюдены условия их использования |
| Телефон | Те же проверки выполнены в браузере физического телефона через тот же сервер домашней сети |
| Бесплатность и хранение | Подтверждён бесплатный режим без автосписаний; провайдерские ответы и ключи не записаны в постоянную базу и Git |

Выходы: воспроизводимые скрипты и страница, датированный отчёт с версиями, успешными пунктами, ограничениями и требуемыми действиями. Не записывать авторизационные данные, приватный профиль аккаунта и полный ответ модели.

Если пункт не подтверждён, основная реализация не начинается. Сначала завершить независимую подготовку, затем запросить точное недостающее действие. Если сервис доказанно несовместим, вернуть на пересмотр ТЗ; не выбирать платный или упрощённый вариант самовольно.

## Проверки по этапам

- В каждой задаче проверять затронутое поведение до передачи результата.
- Backend: pytest, включая повторный импорт, даты/время Москвы, конфликты, сохранение ручных точек, версии и доступ к чужим объектам.
- Frontend: Vitest для параметров, действий редактора и обработки состояний.
- Сквозной сценарий: Playwright; дополнительные живые прогоны и физический телефон фиксируются отдельно.
- После изменения контракта перегенерировать типы и проверить обе стороны.
- По одной успешной сборке, мокам или выбранной библиотеке готовность не объявлять.

## Передача работы

Перед началом занять задачу и файлы в общей таблице. Указать входные документы, ожидаемый результат, зависимости и команды проверки. При передаче перечислить сделанное, незакоммиченные файлы, проверки, блокеры и конкретный следующий шаг.

После настройки Git использовать отдельные ветки/worktree без переключения чужой рабочей копии. Общие документы и память синхронизировать вместе с кодом. Завершённые действия добавлять в журнал; актуальный статус не дублировать личными версиями памяти.
