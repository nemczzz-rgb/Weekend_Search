# База знаний Weekend Search

Статическая база знаний сайта: JSON-файлы в этой папке. Формат описывают типы [types.ts](types.ts), его же проверяет валидатор [scripts/content/validate.mjs](../../../../scripts/content/validate.mjs). Решения и объёмы — в [плане](../../../../docs/project/day-ideas-plan.md), разделы 4 (D2, D6–D8, D14) и 9.

Документ для ChatGPT, Codex и людей, которые наполняют базу. Если правило непонятно или не подходит к данным, нужно остановиться и спросить пользователя, а не придумывать.

## Коллекции

| Файл | Что внутри | Задача |
| --- | --- | --- |
| `places.json` | Места Москвы и Подмосковья | TASK-046 |
| `routes.json` | Маршруты прогулок и городские идеи из 1–6 мест | TASK-054 |
| `events.json` | События с датой | TASK-046 |
| `films.json` | Фильмы по 10 жанрам | TASK-044 |
| `recipes.json` | Рецепты для домашних сценариев | TASK-043 |
| `activities.json` | Отдельные занятия: дома или в городе | TASK-045 |
| `day-ideas.json` | Сценарии дня из 2–3 занятий | TASK-045 |

Пустая коллекция — это `[]`. Файл удалять нельзя.

## Общие правила

1. **Только проверяемые факты.** Адрес, часы, цена, дата события, год фильма — только с источником (`source`) и датой проверки (`checkedAt`, `YYYY-MM-DD`). Источник — https-ссылка на страницу, где факт виден, или `"owner"` для материалов владелицы.
2. **Неизвестное не пишем.** Не нашли часы — поля `hours` нет. Сайт сам покажет «Уточнить перед визитом». Догадки, «примерно», «обычно» — запрещены.
3. **Свои слова.** Описания, шаги, заметки пишутся своими словами. Чужой текст не копируется. Ингредиенты и количества — факты, их можно переносить. Рецепт и список фильмов владелицы (`docs/knowledge-base/owner/`) переносятся без искажений.
4. **Постеры разрешены по поручению Alex071004 от 2026-11-13.** Использовать проверенные локальные изображения с `poster.src`, `alt`, размерами, `source`, `credit` и `checkedAt`. Ссылки на онлайн-кинотеатры и «где посмотреть» остаются вне формата; валидатор отклоняет `url`, `platform`, `watchUrl`.
5. **`id`** — латиница в kebab-case (`roman-pizza`, `gorky-park`), уникален в коллекции и **не меняется** после попадания в `main`: на него ссылаются сохранённые планы пользователей.
6. **Язык — русский.** Названия фильмов — как в российском прокате, оригинальное название — в `originalTitle`.
7. **Пачками.** Одна пачка — один PR: 5 рецептов, один жанр фильмов, 10 мест или 10 сценариев. Каждый PR проходит валидатор и вычитку.

## Поля по коллекциям

Полный формат — [types.ts](types.ts). Ниже главное.

### Место (`places.json`)

Обязательно: `id`, `title`, `kind`, `area`, `durationMinutes`, `note`, `tags`.

Факты (`address`, `hours`, `price`) — объект `{ "value", "source", "checkedAt" }`, у каждого факта свой источник:

```json
"hours": { "value": "Ежедневно 10:00–22:00", "source": "https://…/contacts", "checkedAt": "2026-11-12" }
```

Необязательно:
- `publicSpace: true` — улица, площадь, бульвар; сайт показывает общее описание городского пространства.
- `extraSources` — дополнительные страницы с теми же фактами.
- `mapLink` — ссылка на карточку на карте и адрес в том виде, как их дала владелица.
- `hints` — короткие формулировки без источника из прежних версий (например, «Прогулка без билета»). В них не может быть цифр и цен. **Новые `hints` не добавлять** — нужно найти факт с источником.
- `scheme` — позиция на старой условной схеме, для новых мест не нужна.

### Маршрут (`routes.json`)

`id`, `title`, `subtitle`, `theme`, `area`, `tone` (blue, sage, olive, rust, sand, ink), `days` (1 или 2), `placeIds` (1–6 мест из `places.json`, в порядке посещения), `keywords`. Новое место сначала добавляется в `places.json` (TASK-046), потом используется в маршруте.

### Событие (`events.json`)

`id`, `title`, `dateStart`, `source` (только https, не `owner`), `checkedAt`; по возможности `dateEnd`, `time`, `placeId` или `address`, `price`. Только события с точной датой на официальной странице, на ближайшие 2 выходных. Прошедшие события сайт скрывает сам, удалять их не нужно.

### Фильм (`films.json`)

`id`, `title`, `year`, `genres` (из списка ниже), `origin` (`owner` — из списка владелицы, `research` — найден при исследовании), `source` и `checkedAt` для года и названия. Необязательно: `originalTitle`, `note` — своя мини-аннотация завязки до 100 символов без спойлеров; с ней обязательны `noteSource` (https-страница, подтверждающая завязку) и `noteCheckedAt` (дата проверки). Это отдельные источник и дата от метаданных фильма. Без `note` эти поля не добавлять. `poster` — проверенный локальный постер:

```json
"poster": {
  "src": "images/films/home-alone-1990.webp",
  "alt": "Постер фильма «Один дома» (1990)",
  "width": 480,
  "height": 720,
  "source": "https://www.themoviedb.org/movie/771?language=ru-RU",
  "credit": "TMDB",
  "checkedAt": "2026-11-13"
}
```

Путь относительно `public/`, без ведущего `/`, строго `images/films/<film-id>.webp`. В интерфейсе добавляется `import.meta.env.BASE_URL`, сохраняются размеры и пропорции, изображения ниже первого экрана загружаются лениво. Файл — настоящий WebP, ≤ 300000 байт, до 480 × 720; исходный URL и контрольная сумма записываются в [журнал постеров](../../../../docs/knowledge-base/film-posters.md). Источник и credit обязательны; дата проверяется отдельно от метаданных фильма. Указание источника не означает свободную лицензию. Для TMDB нужны видимая атрибуция и раздел источников по журналу. Без постера или при ошибке загрузки название, год и выбор фильма остаются доступны; изображение не придумывать.

Жанры: `romance` романтика, `comedy` комедия, `drama` драма, `thriller` триллер, `sci-fi` фантастика, `fantasy` фэнтези, `family` семейное кино, `animation` мультфильмы, `adventure` приключения, `cozy` уютное кино. Один фильм может входить в несколько жанров.

В списке владелицы есть франшизы («Гарри Поттер», «Властелин Колец»). Какой фильм серии брать, решает владелица: вопрос задаётся в [issue TASK-044](https://github.com/nemczzz-rgb/Weekend_Search/issues/15), самостоятельно не выбирается.

### Рецепт (`recipes.json`)

`id`, `title`, `yield`, `leadTimeHours` `{min, max}` в часах (0, если готовить можно сразу), `ingredients` по группам (`name`, `amount` числом, `unit`, `note`), `sections` с шагами, `source`, `checkedAt`; по возможности `tips`, `toppings`, `serving`.

Рецепт владелицы `roman-pizza`: `source: "owner"`, `leadTimeHours: {min: 48, max: 72}`, разделы `autolysis`, `kneading`, `fermentation`, `shaping`, `bake-1`, `bake-2`, плюс `tips`, `toppings`, `serving`. Валидатор это проверяет.

### Занятие (`activities.json`) и сценарий (`day-ideas.json`)

Занятие: `id`, `title`, `location` (`home` или `city`), `durationMinutes`, `audience` (`solo`, `pair`, `friends`, `family`), `needs` (что понадобится, может быть пустым), `detail`:
- `{ "type": "recipe", "recipeId": "…" }`
- `{ "type": "films" }` — выбор жанра и фильма
- `{ "type": "steps", "steps": ["…", "…"] }`
- `{ "type": "places", "placeIds": ["…"] }` — только для `location: "city"`

Если занятие нужно начинать заранее, указывается `leadTimeHours` и короткая причина `leadTimeNote` (до 60 символов, со строчной буквы: «тесто 48–72 ч в холодильнике») — её сайт показывает в статусе и в плане.

Сценарий: `id`, `title`, `summary` (до 140 символов), `mode` (`home`, `city`, `mixed`), `activityIds` (2–3 занятия по порядку), `keywords`. `mode` должен совпадать с местами занятий: `mixed` — есть и дом, и город.

`keywords` — слова, которыми люди описывают такой день: по ним работает подбор по пожеланию ([R-WISH](../../../../docs/ux/interaction-rules.md#пожелание-d3)). Обязательно включать бытовые слова: «фильм», «кино», «дома», «спа», «ванна», «готовить», «пицца», «книга» — те, что подходят идее.

## Как проверить

```bash
node scripts/content/validate.mjs
```

Выводит счётчики и ошибки. Флаг `--release` превращает недобор объёмов D14 в ошибку; так проверяется PR выпуска. CI запускает валидатор на каждый PR.

## Как сдаёт работу ChatGPT

ChatGPT не имеет доступа к репозиторию. Он отвечает:
1. одним JSON-блоком — массивом записей строго по формату выше;
2. журналом поиска: что искал, какие источники отбросил и почему;
3. списком того, что не удалось подтвердить.

Codex добавляет записи в нужный файл в ветке `task-0NN-kb-…`, запускает валидатор и открывает PR. Журнал и список неподтверждённого переносятся в описание PR.
