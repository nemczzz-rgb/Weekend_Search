# Weekend Search

Проект сайта для поиска интересных мест и событий на выходные по выбранной пользователем локации или району.

Утверждены [ТЗ первой версии](docs/project/technical-specification.md) и [план реализации](docs/project/implementation-plan.md). Выполняется обязательная проверка интеграций TASK-003. Основное приложение ещё не реализовано.

Стек: React/TypeScript/Vite, Python/FastAPI/Pydantic 2, SQLite. Выпуск локальный, в том числе в домашней сети; дополнительный бюджет — 0 рублей. Фактический результат проверок: [memory/CURRENT.md](memory/CURRENT.md).

## С чего начать

1. Прочитать [правила работы](AGENTS.md).
2. Прочитать [контекст проекта](CONTEXT.md).
3. Проверить [текущее состояние](memory/CURRENT.md) и [задачи](memory/TASKS.md).
4. Перед изменениями обозначить свою задачу и затрагиваемые файлы; после работы обновить общую память.

## Проверить интеграции до разработки

Запускать команды из корня проекта:

```powershell
python scripts/probes/check_integrations.py --kudago --codex
python scripts/probes/serve_map_probe.py --lan
```

Первая команда проверяет живые данные и статус CLI; вторая запускает только диагностическую страницу карты, не сайт. Для App Server, бесплатного ключа и физического телефона следовать [инструкции TASK-003](scripts/probes/README.md). Пока контрольная точка не пройдена, команды запуска основного приложения отсутствуют.

[Фактический отчёт интеграций](docs/architecture/integration-report.md): Codex проверен; KudaGo отвечает 403, карта и физический телефон ожидают проверки.

## Структура

```text
.
├── AGENTS.md                 # Общие инструкции всем агентам
├── CONTEXT.md                # Переносимый контекст и основные принципы
├── apps/
│   ├── web/                  # Место для будущего фронтенда
│   └── api/                  # Место для будущего бэкенда
├── packages/                 # Будущие общие модули при реальной необходимости
├── assets/                   # Исходные визуальные материалы
├── docs/
│   ├── project/              # Утверждённые ТЗ и план реализации
│   ├── decisions/            # Согласованные решения и их причины
│   ├── architecture/         # Будущая архитектура и контракты
│   ├── design-system/        # Будущая дизайн-система
│   ├── testing/              # Будущая стратегия проверки
│   └── deployment/           # Будущие инструкции по окружениям и выпуску
├── memory/
│   ├── CURRENT.md            # Единственный актуальный статус проекта
│   ├── TASKS.md              # Общая очередь и владельцы задач
│   ├── LOG.md                # Краткая история выполненной работы
│   └── handoffs/             # Передача незавершённой работы
```

Подробные назначения разделов: [карта документации](docs/README.md) и [правила памяти](memory/README.md). Папки `apps/web` и `apps/api` — организационные заготовки, а не решение о независимом запуске или деплое сервисов. Их можно изменить после согласования архитектуры.

## Работа с разных аккаунтов

Контекст хранится в обычных Markdown-файлах внутри проекта и не зависит от истории чата или локальной памяти агента. Чтобы передать работу, нужно передать актуальные файлы проекта, включая `memory/`, и прочитать их в новой сессии.

Проект хранится в публичном GitHub-репозитории [nemczzz-rgb/Weekend_Search](https://github.com/nemczzz-rgb/Weekend_Search). Работа идёт в отдельных ветках и попадает в `main` через Pull Request. CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) собирает интерфейс и запускает проверки. Правила ветвления и совместной правки памяти: [AGENTS.md](AGENTS.md#работа-с-git-и-github).
